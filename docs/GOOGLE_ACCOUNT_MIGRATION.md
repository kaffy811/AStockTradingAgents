# 旧账户 Google 绑定迁移：待批准的人工操作方案

**本方案未执行。普通登录没有迁移能力；不会根据邮箱、密码字段或管理员声明自动合并。** 新 Google-only 机制不改变旧账户 UUID、密码 hash、角色、报告或自选股。已有 google_sub 绑定继续使用，停用账户不能通过迁移自动恢复。

## 受理与证据

每个账户单独建立审计工单，至少包括：工单 ID、目标 app_users.id、申请时间、操作人、独立审批人、原 Google 绑定快照（仅标识，不含凭证）、是否管理员、旧账户归属核验记录、Google 身份核验记录、预期变更及回滚条件。

需要两份独立证据：

1. **旧账户归属**：优先使用仍有效的原账户已鉴权会话确认的不可变用户 UUID，并由支持人员独立复核。无有效会话时走组织认可的人工身份/持有历史证明流程。仅能接收同邮箱邮件、知道用户名或自称管理员都不够。不要在普通登录页恢复密码表单，不通过临时公开 API 暴露原密码验证或任意绑定功能。
2. **新 Google 身份**：在单独受控的迁移验证流程中生成随机、有期限、只能使用一次的挑战；用现有 Google verifier 校验 RS256、issuer、audience、exp、已验证邮箱和匹配 nonce，记录验签得到的 sub、client ID、验证时间及挑战摘要。不得采用截图、用户提交的纯 sub/email、未验签 JWT 解码结果作为证明。不要将原始 ID token、密码或现有 access/refresh token 放进工单、SQL、命令参数、终端录屏或日志。

本交付提供**审阅方案及默认回滚的 SQL 模板**，未提供或启用新的在线迁移接口。上述独立证据收集流程需要在实际执行前单独审批并完成；缺少任一证据就保持账户未绑定。

## 普通账户操作计划

1. 审批人核对：目标是准确 UUID、旧 google_sub 为空、账户启用且不是管理员；新 sub 未属于其他账户。不能把邮箱查到的另一个账户当作目标，不能更换 UUID 或搬移外键。
2. 在获准的隔离副本演练，备份目标行与其报告/自选股归属计数、审批记录和精确回滚条件。未获批准前不得连接共享 Supabase 执行本步骤。
3. 使用 [审阅 SQL 模板](GOOGLE_ACCOUNT_MIGRATION_REVIEW.sql)。模板默认 ROLLBACK，不会提交；只有二次审批明确授权后，才生成独立的实际执行版本。UUID、已验签 sub 应通过受控参数注入，不拼接任意 SQL。
4. 锁定目标行，只更新 google_sub/updated_at，其他字段不写。确认恰好更新一行、没有约束冲突；零行、多行或任何状态变化都回滚。唯一约束是最终安全边界，不能临时移除。
5. 审计记录保留执行 SQL 校验和、审批人、执行人、事务结果、更新前后 sub、原 UUID/权限/资源计数、时间。记录保存在受控、不可随意改写的审计系统；不要保存密码或 JWT。两人分工核对后才允许提交。
6. 申请人重新走普通 Google 登录，验证 access token 的 sub 仍是原 app_users.id，再验证其原报告、历史、自选股及原权限归属。不得把新 Google sub 当成项目 JWT 的 user ID。

## 管理员账户

普通模板明确 `is_admin=false`，不能绑定管理员。管理员迁移必须是独立工单和双人审批，核对组织身份及已有管理员权限来源、验证 Google 身份、评估会话安全后单独生成按 UUID 锁定的变更；只改变 google_sub，**绝不修改 is_admin**。本次没有默认管理员、自动提权、应急密码登录或公开管理员注册入口。

切换前必须规划现有管理员的可用 Google 绑定或人工运维路径，否则旧管理员会因安全策略被正常阻止登录。不能为避免锁定而取消邮箱冲突保护。没有可验证管理员时，保持账户准入维护状态，通过已有基础设施管理权处理，不创建公开后门。

## 撤销与回滚

- 未提交事务直接回滚。
- 已提交的绑定只能在另一个批准的操作中，按 UUID + 本次精确 sub + 预期账户状态检查后撤销/更正；不能批量清空 google_sub，也不能依据邮箱撤销。
- 不删除用户、邀请码、密码字段，不重建数据库，不移动报告、自选股或权限。不对 Google 列执行 Alembic downgrade。
- 应用镜像回滚与账户迁移撤销是两项独立审批。已有无状态 JWT 不会因绑定字段更改立即撤销，需结合原会话有效期及既有停用流程评估，不能声称绑定迁移能即时终止所有会话。
